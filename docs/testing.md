# Testing

geo-api tests three separate things: source parsing, the numerical measurement model, and API/database publication.

## Local commands

```sh
uv sync --frozen --all-groups
uv run ruff format --check .
uv run ruff check .
uv run mypy src/geo_api
uv run alembic upgrade head
uv run pytest -q
```

Tests that exercise routes and persistence use PostgreSQL 17. They do not substitute SQLite. Set `DATABASE_URL` to a disposable test database before running integration tests; test setup may clear geo-api tables. Lifecycle tests exercise worker timeout, crash, cancellation and descendant reaping, malformed child protocol, admission disconnects, transaction rollback, database unavailability, and startup cleanup.

## Fixtures and numerical references

`tests/fixtures/sample.kml` is a small Bengaluru polygon with a KML `Placemark` ID and ExtendedData. `partial.kml` exercises a polygon, point, and mixed geometry outcome. ZIP/Shapefile fixtures are synthetic and generated by the tests with PyShp so the `.shp`, `.shx`, `.dbf`, `.prj`, and encoding paths are real.

Numerical assertions use the checked-in `tests/fixtures/geographiclib_reference.json`, generated by `scripts/generate_reference_fixtures.py` with GeographicLib's WGS84 geodesic inverse and polygon accumulator. Polygon boundaries in these comparisons follow the same shortest-geodesic edge model and explicit shell/hole roles. Regenerate the fixture with `uv run python scripts/generate_reference_fixtures.py`. The thresholds are applied separately from the production densification convergence checks: `max(0.01 m², 0.1% of reference area)` and `max(0.001 m, 0.1% of reference length)`.

Coverage includes low-level projected input, Bengaluru, equatorial and antimeridian features, polar KML, holes, multipart overlap, invalid/open rings, unsupported geometry, source Z/M values, deleted DBF rows, Unicode properties, malformed CRS, and ZIP/XML abuse cases. These fixtures do not prove every CRS operation or all shapes near the 100 km limit; unsupported and unresolved boundary cases must fail explicitly.

Admission and worker tests cover streamed body limits without `Content-Length`, slot release, upload receive deadlines, disconnect cancellation, process-group cleanup, and raw child-protocol line/depth limits. PostgreSQL integration cases cover real publication, failed-file persistence, cascade deletion, and database rejection of non-finite measurements.

## Docker smoke check

The `docker-smoke` GitHub Actions job builds the Linux AMD64 image, waits for `/health/ready`, uploads the checked-in KML, and checks the terminal file response. Run the same reviewer flow locally with `docker compose up --build` and the README curl example.
